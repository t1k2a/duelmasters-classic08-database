# Google Search Console 週次運用手順

対象サイトは次のGitHub Pages URLです。

- URL-prefixプロパティ: `https://t1k2a.github.io/duelmasters-classic08-database/`
- サイトマップ: `https://t1k2a.github.io/duelmasters-classic08-database/sitemap.xml`

## 初回登録と所有権確認

1. Google Search Consoleで「プロパティを追加」を選ぶ。
2. 「URLプレフィックス」を選び、末尾の `/` を含む対象URLを入力する。
3. このサイトのGA4プロパティを管理できるGoogleアカウントなら、「Google Analytics」を使って所有権を確認する。
4. GA4で確認できない場合は「HTMLタグ」を選び、提示されたmetaタグをトップページの`<head>`へ追加してデプロイする。公開ページでタグを確認してから「確認」を実行する。
5. 所有権確認後、「サイトマップ」に `sitemap.xml` を送信する。

GitHub PagesのサブディレクトリURLであるため、ドメインプロパティではなくURL-prefixプロパティを使います。所有権確認用の秘密鍵、サービスアカウントJSON、Cookieなどの秘密値は、リポジトリやIssue、Pull Requestへ保存しません。

## 毎週の確認

毎週同じ曜日に、前回と同じ期間条件で次を確認します。

1. 「検索パフォーマンス」で直近7日と直前7日を比較する。
2. 合計クリック数、合計表示回数、平均CTR、平均掲載順位を記録する。
3. 「クエリ」で表示回数上位と、表示回数は多いがCTRが低い語句を確認する。
4. 「ページ」で `/guide/`、`/deck-guide/`、`/guides/` のクリック数と表示回数を確認する。
5. 「ページのインデックス登録」で、登録済みページ数と未登録理由の増減を確認する。
6. 「サイトマップ」で最終読み込みが成功していることと、検出されたページ数の急減がないことを確認する。

## 未登録・重複ページの診断

### 「クロール済み - インデックス未登録」

1. URL検査でHTTP 200、インデックス登録許可、Googleが選択したcanonicalを確認する。
2. `noindex`、robots.txtによるブロック、誤ったcanonical、ソフト404がないか確認する。
3. 類似ページと比べて、検索意図に固有の本文、title、descriptionがあるか確認する。
4. ハブや関連カード・ガイドから到達できる内部リンクがあるか確認する。
5. 修正後にサイトマップへcanonical URLだけが含まれていることを確認し、重要ページのみURL検査から登録をリクエストする。
6. 次週以降も状態を追い、短期間に同じURLへ登録リクエストを繰り返さない。

### 「重複しています」または別URLがcanonicalに選ばれた場合

1. URL検査で「ユーザーが指定したcanonical」と「Googleが選択したcanonical」を比較する。
2. クエリパラメータ、末尾スラッシュ、旧URLなど、同じ内容を返すURLを洗い出す。
3. 残す正規URLを一つ決め、各ページのcanonical、サイトマップ、内部リンクをそのURLへ統一する。
4. 不要な旧URLを安全に転送できないGitHub Pages環境では、旧URLをサイトマップと内部リンクから除き、正規URLの固有性を高める。
5. 意図的に別ページとして残す場合は、title・見出し・本文・検索目的が十分に異なることを確認する。

## 自動化方針

当面はSearch Console画面から週次で記録します。十分なデータが蓄積し、手動集計が継続的な負担になったことを確認するまではSearch Console APIを自動化しません。将来APIを導入する場合も、認証情報はGitHub Actions Secretsなどの秘密管理へ置き、リポジトリには保存しません。
