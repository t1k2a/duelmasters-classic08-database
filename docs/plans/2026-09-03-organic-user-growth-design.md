# 外部連携を使わないオーガニックユーザー増加施策 設計

## 目的

デュエマ クラシック08 データベースの月間アクティブユーザーを、外部の大会主催者・YouTuber・発信者への個別連携に依存せず増加させる。

直近のGA4レポート（2026-07-21〜2026-08-17）では、47アクティブユーザー、平均エンゲージメント時間3分44秒、トップ検索画面の直帰率27.1%を記録している。訪問後の利用品質より認知不足を主要課題と判断し、暫定的な最初の目標を月間100アクティブユーザーとする。

## 対象外

- 大会主催者・YouTuber・記事執筆者へのDMや個別営業
- 相互紹介やスポンサー施策
- 有料広告
- 現行デュエマ全体への対象拡大
- AIチャットを主軸にした集客
- 内容の薄いページの機械的な大量生成

## 戦略

施策リソースを次の比率で配分する。

- SEO・検索コンテンツ: 60%
- X・noteの自社発信: 25%
- 共有・再訪機能: 15%

成長ループは以下とする。

```text
検索・自社SNS投稿
  → 課題別の解説ページ
  → レシピ閲覧またはカード検索
  → デッキをコピーして編集
  → 40枚完成
  → URLまたは画像を共有
  → 新規ユーザー流入
```

## コンテンツ設計

### 基礎SEOページ

最初に次の3ページを用意する。

1. クラシック08の始め方
2. クラシック05と08の違い
3. クラシック08の殿堂・お助けカード一覧

### 主要デッキページ

次の5ページを優先する。

1. シノビドルゲーザ
2. 黒緑速攻
3. ネクラフェルナンド
4. ボルメテウス
5. 初心者向け低予算デッキ

各デッキページは最低限、概要、主要カード、基本的な動かし方、弱点・対策、サンプルレシピ、関連カード、「このデッキをコピーして編集」導線を持つ。根拠のない大会実績・Tier断定や、裏付けのない価格情報は掲載しない。

### SEO品質要件

- ページごとに固有のtitle、description、canonical、OGPを設定する。
- 見出しと本文は検索キーワードの羅列ではなく、利用者の疑問に直接答える。
- JSON-LDを使う場合は画面に表示される内容と一致させる。
- 基礎ページ、デッキページ、カード詳細、レシピ詳細の間に文脈のある内部リンクを置く。
- 既存の約19,000 URLを一律に改稿せず、Search Consoleの実測から優先URLを決める。
- 重複・薄いレシピページは、統合、canonical、noindexのいずれが適切かを実データで判断する。

## プロダクト導線

- デッキ解説から完成レシピを読み込み、既存デッキビルダーで編集できるようにする。
- 共有されたデッキには「このデッキをコピーして編集」を明示する。
- 40枚完成後に限り、押し付けにならない共有提案を表示する。
- デッキ共有画像にデッキ名、サイト名、復元URLへ到達できるQRコードを含める。
- カード検索条件をURLで再現・共有できるようにする。
- PWAインストールは初回訪問直後ではなく、価値を体験した利用者へ案内する。

## 自社発信

1つのテーマをサイト、note、Xへ再編集して使用する。

- サイト: 検索意図を満たす完全版
- note: 背景や判断を含む読み物
- X: 要点、対策カード、デッキ画像など3〜4投稿

週1テーマを基本とし、同じ告知の反復や1日複数回の連投は避ける。投稿URLには媒体・企画を識別できるUTMパラメータを付ける。

## 計測設計

### 暫定KPI

- 月間アクティブユーザー: 47 → 100
- オーガニック検索流入ユーザー数
- Search Consoleの検索表示回数とクリック率
- 40枚デッキ完成数
- デッキコピー数
- デッキ共有数
- 共有URL経由の新規ユーザー数
- 7日以内の再訪率

### イベント

既存の同意取得後GA4送信を維持し、少なくとも次を計測する。

- `view_card_detail`
- `copy_deck`
- `deck_complete`
- `share_deck`（既存。共有方法をパラメータで区別）
- `pwa_install_prompt`
- `pwa_install`
- `content_cta_click`（コンテンツIDと遷移先種別を付与）

イベントは同じ操作で重複発火しないようにし、カード名や自由入力など不要な高カーディナリティ値・個人情報を送らない。

## 30日間の進め方

### 第1週: ベースラインと計測

- Search Consoleの所有権・サイトマップ・インデックス状況を確認する。
- GA4イベントとUTM命名規則を整える。
- 現在値を保存し、週次レポートで比較可能にする。

### 第2週: 基礎SEOページ

- 基礎SEOページ3本を作成する。
- 関連する既存ページとの内部リンクを追加する。
- 構造化データ、OGP、モバイル表示を検証する。

### 第3週: 主要デッキページ

- 優先デッキ5本を作成する。
- デッキコピー・編集導線を接続する。
- 共有URLから同一デッキが復元されることをE2Eで確認する。

### 第4週: 配信と改善

- 各ページをnoteとX向けに再編集する。
- 検索表示、クリック、コンテンツからの行動、共有を比較する。
- 翌月は最も反応のよい検索意図・デッキ系統に制作を集中する。

## エラーとフォールバック

- Search ConsoleやGA4が未設定でもサイトのビルドと閲覧は失敗させない。
- デッキデータが欠落・不正な場合はコピー操作を無効にし、利用者へ理由を表示する。
- 共有API非対応環境ではURLコピーまたは画像ダウンロードへフォールバックする。
- QRコード生成失敗時も、従来の共有画像出力は継続できるようにする。
- JavaScript無効時でも解説本文と主要リンクは読める静的HTMLとする。

## 検証

- `npm test`
- `npx tsc --noEmit`
- `npm run build`
- SEOメタデータ、canonical、構造化データの静的検査
- 主要8ページのリンク切れ検査
- デッキコピー、40枚完成、共有、復元のE2E
- モバイル・PC、ライト・ダークテーマの目視確認
- GA4を無効化した状態と同意後の状態の両方で操作確認

## 完了条件

- 主要8ページが公開対象の静的生成物に含まれる。
- 各ページから関連カード・レシピ・デッキ編集へ移動できる。
- 主要イベントが重複なく計測される。
- Search ConsoleとGA4で週次比較に必要な指標を取得できる。
- 全テスト、型チェック、ビルド、E2Eが成功する。
- 公開後4週間のデータをもとに、継続・修正・中止を判断できる。
