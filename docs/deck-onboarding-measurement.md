# デッキの入口とコピー計測

## 利用者向けの変更

- 空デッキから「サンプルデッキを見て試す」で初心者向けガイドへ移動できる。内容を確認してから40枚のサンプルをコピー・編集する。
- レシピ一覧の「読込」は「このデッキをコピーして編集」に変更する。既存デッキがある場合は上書き確認を維持する。
- 一覧からのコピーも、URL経由と同じくカードID・枚数・合計を検証する。欠落カードや不正な枚数を黙って補正せず拒否する。保存失敗・キャンセル時は現在のデッキを保持する。

## イベント定義

両方の入口で、検証・保存に成功した後だけ既存の `copy_deck` を送る。
送信項目は `content_id`（レシピID）、`card_count`（1〜40）、`entry_point` のみ。
`entry_point` は `recipe_list` または `recipe_url` に限定する。
旧データとの互換性のため `entry_point` は任意。GA4で内訳を集計するには、このイベントパラメータのカスタムディメンション設定を別途確認する必要がある。

URL経由は既存のページ内一度だけの制御を維持する。一覧で利用者が再度上書きを承認してコピーした場合は別の成功操作として数える。再描画・キャンセル・検証エラー・保存失敗は数えない。
コピー操作は `add_to_deck` や `deck_complete` として重複計測しない。
デッキ名、カード名、自由入力、IP、認証情報は追加イベントへ含めない。
同意前の操作を後から送信しない。イベント件数は人数・投稿数・CVRを意味しない。

## 確認用アクセスの除外

localhost、127.0.0.1、::1 のローカルアクセスでは計測しない。
本番を確認する場合は最初に `?analytics=off` を付けて開くと、そのタブのセッション中は記事への移動後もタグ・イベント送信を停止する。
`?analytics=on` でセッションの停止指定を解除するが、同意が必要な点は変わらず、ローカルホストでは解除されない。
セッション保存の使用ができない場合は安全側で計測を停止する。

この指定は既に送ったイベントを取り消さず、別タブ・別端末・過去の検証アクセスも自動的には除外しない。共有リンクに検証用指定を付けて配らない。
GA4管理画面の内部トラフィック定義や除外フィルターは変更していない。

## 検証範囲

`npm test` と型検査、静的サイトビルドに加え、`scripts/e2e-deck-onboarding.mjs` でPC/スマホ・ライト/ダークを隔離ブラウザで検証する。
GAタグは空のローカル応答へ置換し、実Googleタグやcollect先への通信をさせない。実利用者の保存デッキやブラウザプロファイルは使用しない。
ローカルのイベントキュー確認は、本番GA4での受信・集計を保証しない。
