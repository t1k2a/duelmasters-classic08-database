# 画面表示の計測（panel_view）

GA4への同意後のみ、SPAの最前面の画面が変わったときに送信する。
`panel_name` は search（検索一覧）、deck（マイデッキ）、recipe（カードから開くレシピ一覧）、card_detail（カード詳細）の固定値のみ。
検索一覧の初回表示、パネルを閉じた後の一覧への復帰も数える。同じ画面内の再描画や別カードへの切替は数えず、閉じて再度開くと再計上する。
静的カード・レシピ個別ページは対象外。同意前の履歴は送らず、同意時の画面から開始する。

新イベントでは検索語・デッキ名・本文・カードIDを送らない。イベントのpage_locationとpage_titleは固定、page_referrerは空にする。さらに初期config・全手動イベントも下記のとおり保護する。ただし拡張計測の自動イベントは別途確認が必要で、安全を保証しない。

既存設定は同意後のみタグをロード、Googleシグナル・広告パーソナライズ無効。未成年対象サイトとしての利用条件・同意の適切性は本変更だけでは確認完了しない。本番公開前に運営者が別途確認する。セッション録画・ヒートマップ・新規解析事業者の導入は行わない。

表示回数は閲覧時間・注視・読了を示さない。利用割合は対象イベントのユニークユーザー数を、同期間の計測対象ユーザー数で割る。イベント回数÷ユーザー数は利用率ではない。少人数・内部トラフィックTEST・PV二重計測未確認の制約を残す。
GA4画面でpanel_nameを通常レポートに表示するにはカスタムディメンション登録が必要になる場合がある。本変更はGA設定を変更せず、本番テストイベントも送らない。

## 追加監査: 既存GAの入力値経路

- 既存初期configはデフォルトのpage_viewを送る。SPAのURLには検索語qが入り、デッキに応じdocument.titleも変更されるため、従来はURL/タイトルの既定値を通じて送信し得た。
- 本PRでは初期configとすべての手動イベントのpage_locationからquery/hashを除外し、page_titleを固定、参照元をoriginだけに削減。手動イベントは許可リスト化し、card_name/deck_name/top_cardsなど名称文字列を破棄する。
- その結果、URL上のUTMによる流入の詳細や参照元ページの詳細が以前と同じようには取得されなくなる可能性がある。施策前後の単純比較には注意。
- ただし拡張計測のHistory page_viewはsend_page_view:falseでも停止せず、サイト内検索がONならqからsearch_termが取得される。フォームや外部リンクも別の自動取得経路となる。クライアント側の引数テストだけではこれらを保証しない。
- **公開保留条件:** 管理画面で拡張計測（History/サイト内検索/フォーム/外部リンク）およびURLデータ編集設定を確認し、自由入力を送らない設定・挙動を別途確認する。本PRで管理設定は変更しない。

公式資料: [page_viewと履歴計測](https://developers.google.com/analytics/devguides/collection/ga4/views)、[拡張計測のイベントと検索語](https://support.google.com/analytics/answer/9216061)、[データ編集](https://support.google.com/analytics/answer/13544947)。

### 2026-11-15 管理画面の読み取り確認

拡張計測ON、ページロード＋履歴page_view ON、サイト内検索ON（q/s/search/query/keyword）、フォーム・外部リンク等ON。メールアドレス編集ON、クエリパラメータ編集OFF。設定変更はしていない。

公開前の最小管理対応案（別途承認・操作が必要）:
1. 拡張計測の「ブラウザの履歴イベントに基づくページの変更」「サイト内検索」をOFFにする。SPA内の画面変化はpanel_viewで測る。初回page_viewは安全化したconfigで1回送る。
2. フォーム操作・離脱クリック（外部リンク）もOFFにする。自由入力を含むリンク先URLやフォーム情報の自動取得を避け、購買リンクは許可リスト適用済みの手動イベントで代替する。他の自動イベントも送信パラメータを確認する。
3. URLデータ編集を有効にし、少なくともq/s/search/query/keyword/deck/dと任意の追加検索パラメータを対象にする（防御の追加。任意のデータを完全に保護する保証ではない）。
4. 承認された検証環境でネットワーク送信内容を確認してから公開を判断する。本作業では本番イベント送信なし。

拡張計測を一括OFFにする方法もあるがscroll/download/video等の指標が止まるため、本PRで無断変更しない。既存UTMの詳細を保つ目的でクエリをそのまま戻すこともしない。
