## 読む順番

1. [プロジェクトREADME](../../README.md)で、サービス全体と収録範囲・ビルド方法を把握する。
2. この案内から[カード収録監査](card-coverage-audit-2026-10-03.md)へ進み、対象と方法・検証限界を読んでから個別の欠落表を確認する。
3. [既知の欠落・取得状況](../../data/seeds/known_gaps.md)で、過去の取得記録と訂正事項を確認する。
4. 実データや判定を確認する場合は、下表のJSON・実装を読む。

## 調査資料と確定・反映済みデータの違い

- **調査資料**は、特定の時点・基準コミットで確認した事実と候補を記録する。2026-10-03監査では対象内の確定欠落4種、追加候補12種（DMC45の5種と追加表の7種）、対象年代・元商品が未確定の13種（最初の表の3種と特別商品表の10種）を区別している。網羅的な欠落総数ではなく、別記のプロモ境界確認対象等も含めた総数ではない。
- **公開JSON**は、サイトに反映されている内容を確認するためのデータ。監査で欠落が確定しても、JSONへ追加済みとは限らない。監査時点の2,251カード・16,813レシピは収録件数であり、全対象カードの完全収録や全レシピの08適合を示さない。
- **seed JSON**は、対象範囲や制限・分類の入力。機械可読であることと、全項目の根拠が確定・最新であることは別。たとえばDMC11/12の製品名・年月は監査で訂正されているが、seedへの反映は別作業として残っている。

この監査ではカードJSON・seed JSONを変更していません。公式カードページの存在、対象年代の確認、固有カードの欠落、再録（printing）の欠落、データへの反映を分けて読んでください。

## 更新時の注意

- 調査日、基準コミット、照合方法、出典、判定理由と未確認事項を残す。候補を確定へ変更する際は、対象商品・発売／配布時期の根拠を確認する。後年の再録や雑誌の号数だけで初出・対象外を決めない。
- 件数はカード種類・printing・レシピを区別する。名称の部分一致や別IDだけで同一カード・新規欠落と判断せず、監査と[known_gaps.md](../../data/seeds/known_gaps.md)の記述も照合する。
- 調査文書の更新とカード／seedの変更・再取り込みは分ける。不完全な`data/raw/`で公開カタログを再生成しない。
- rawがない環境のビルド確認は、[プロジェクトREADMEの手順](../../README.md#ローカルで動かす)に従い、検証用コピーで`BUILD_REUSE_CARDS_JSON=true npm run build`を使う。既存カードJSONの形式を検証して再利用する方法であり、rawの取り込みや収録の完全性は検証しない。他の公開生成物は更新される。
- ファイル追加・移動時はこの案内と相対リンクを更新する。変更に応じた検証と、[AGENTS.md](../../AGENTS.md)に従うビルド・Reviewerレビューを行う。
