# デッキ作成の計測と確認範囲

登録不要・端末内保存の形式は変更しない。利用者のデッキ名、カード名、自由入力、IP、認証情報は新しいイベントに含めない。

| イベント | 意味 | パラメータ |
| --- | --- | --- |
| `view_card_detail`（既存） | カード詳細を開く | `card_id` |
| `add_to_deck`（追加） | カードを1枚追加できた | `card_id`、追加後の合計`card_count` |
| `deck_complete`（既存） | 追加操作で40枚に到達 | `card_count: 40` |

`deck_complete`は40枚到達であり、採用制限への適合や購入完了ではない。既存の発火条件は維持する。40→39→40枚と編集した場合には再到達として発火し得る。上限による追加拒否、再描画、保存復元だけでは追加・完成イベントを発火しない。新規の開始イベントや別名の完成イベントは追加しない。`add_to_deck`の合計1枚を空デッキからの開始として分析できるが、イベント件数をそのまま利用者数とは見なさない。

## 同意と二重計測

コードでは同意後にのみタグを読み込み、`__gaLoaded`で初期化を一度に制限している。明示的な`page_view`追加はない。隔離ブラウザではタグ読込のリクエストをローカルの空応答に置換し、初回同意後の要求1回・`config`1回・明示`page_view`0回を検査する。未同意時はタグ要求0回。実Googleタグもcollect先も通信させないため、この検証は本番の受信や拡張計測の自動履歴イベント数を保証しない。

本番管理画面の拡張計測設定、内部トラフィック定義、除外フィルターの現在値は、この作業では取得していない。設定の変更もしていない。二重計測を断定する根拠がないため、`send_page_view`や履歴同期の実装は変更していない。

次回の確認では、許可された非公開の管理画面で履歴変更に基づくページビュー設定を確認し、初回表示・検索条件変更・詳細開閉を区別して、送信イベントとの対応を調べる。自動/手動のページビューを併用する場合は重複を避ける設計が必要。`send_page_view: false`だけでは拡張計測の履歴イベントを停止しない。[Google公式のページビュー仕様](https://developers.google.com/analytics/devguides/collection/ga4/views)

内部トラフィック除外は現在値を確認し、必要ならまずTestingで対象を確認してから適用を判断する。Activeの除外は除外したデータを後から復元できないため、今回変更しない。実IPやプロパティ識別子を公開ドキュメントへ記載しない。[Google公式の内部トラフィック除外手順](https://support.google.com/analytics/answer/10104470)

## ローカル検証

`scripts/e2e-deck-progress.mjs`は一時ブラウザコンテキストとローカルサーバーを使う。`QA_BASELINE=1`で変更前の表示記録、通常実行でPC/スマホ・Enter操作・保存復元・追加/完成イベントの検査を行う。実利用者のブラウザプロファイルや保存デッキは使用しない。生成する結果とスクリーンショットは`QA_ARTIFACT_DIR`で作業ツリー外へ保存する。

## X共有イベントの解釈

`share_deck` の `method: 'x'` は、有効な枚数のデッキでX共有ボタンから
intent URLを開こうとした操作を示す。投稿完了やX画面の表示成功は確認しない。
`window.open(..., 'noopener')` は正常に開いても `null` を返すため、戻り値を
イベント送信の条件にしない。ポップアップがブロックされた場合も操作に含まれる。
未同意・拒否時は共通の同意チェックで計測を抑止する。

これはクライアント実装の定義であり、GA4での実受信を保証するものではない。
イベント件数を投稿数・売上・利用者数として扱わず、イベント数÷ユーザー数を
CV率とは呼ばない。
