# 本人用 GA4 ローカルレポート

GA4 の実測値・流入元・投稿別ディメンションは本人用です。自動の非公開配送は未確立です。公開 Actions は取得せず、手動実行でも固定の状態メッセージだけを表示します。成功は取得成功を意味しません。公開リポジトリのログ、Summary、artifact、commit、PR、Pages は非公開保存先ではありません。

## 本人の端末での手順（実測は明示的に実行）

1. 本人のみがアクセスできる、共有・公開・クラウド同期されない場所に clone し、ルートで `npm ci` を実行します。Windows はフォルダーのセキュリティ設定で本人だけのアクセスを確認してください。Unix では保存ディレクトリを 0700、ファイルを 0600 で作成します。Git 除外は OS のアクセス制御や暗号化の代わりにはなりません。
2. 既存のサービスアカウント JSON が本人の端末に安全に保存済みの場合だけ、その絶対パスを `GOOGLE_APPLICATION_CREDENTIALS` に設定し、`GA4_PROPERTY_ID` を設定します。値は端末の環境変数、または Git 除外済みのルート `.env` に保存します。JSON はリポジトリ外に置きます。内容を表示・貼付・コミットしないでください。新規キー作成、権限変更、Secrets 変更はこの手順に含みません。
3. オフラインの動作確認は `npm run ga4:report:mock`。認証を使わず合成データだけで生成し、ファイル名と本文に mock を明記します。
4. 本人が実測取得を実行する場合は `GA4_MOCK` を未設定にし、`npm run ga4:report` を実行します。`--local` が必須で、CI 環境では mock を含め拒否します。任意の出力先や stdout へのレポート出力はありません。
5. clone 直下の `.private-reports/` の最新の `real-*.md` を端末で開きます。mock は `mock-*.md`。毎回新しいファイルを作り、既存レポートを上書きしません。生成先は Git 除外され、`public/` 外です。リポジトリルートを Web 配信しないでください。`git add -f` や生成物の公開場所へのコピーは禁止です。

## 失敗時

CLI は固定メッセージと終了コード 1 のみを返し、生の API 応答・エラー・プロパティ ID・認証情報・実数値を出しません。ローカル実行であること、引数、環境変数、既存 JSON の存在と読み取り権限、保存先が通常ディレクトリで書き込み可能なことを本人の端末で確認してください。API 到達性・既存権限・GA4 Data API の利用可否は本人が確認する後続作業です。認証が利用できなければ実測は止め、mock 成功を実測成功として扱いません。

## 検証と残る作業

`npm test` は API client の fixture と CLI の拒否動作を検証します。`npx tsc --noEmit` は型チェックです。これらは実データの正しさ、認証、GA4 設定を検証しません。

この変更は既存の公開レポート・履歴・Actions のログや artifact を削除しません。過去の公開物は非公開化されません。削除や認証の整理は別途判断が必要です。main にマージされるまでは旧 workflow が動作し得ます。自動配送を再開するには本人だけが閲覧できる配送先と認証方式の別設計が必要です。
